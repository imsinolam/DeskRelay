# DeskRelay 0.2.1

Date: 2026-08-18

## Changes

- The GitHub documentation is now organized into user guides, architecture, development collaboration, release, and website-material sections. Common entry points use clear Chinese names, while historical preview notes are grouped in one archive.
- Added step-by-step first-use guides for the LAN mobile page and the public Relay, including mobile password setup, server deployment, validation, and rollback.
- The mobile terminal switcher now shows only states that need attention, such as current, switching, running, approval required, input required, starting, or error.

## Fixes

- DeskRelay no longer opens ChatGPT or WorkBuddy during background startup, restart, or automatic recovery. An explicit terminal or task selection from the web page or ClawBot can still start the matching desktop application when needed.
- Fixed explicit mobile switching being unable to retry a desktop application after an earlier connection failure.
- Fixed Codex approvals disappearing before the desktop owner confirmed them. The web page and ClawBot now keep the real pending approval visible after transport timeouts or unconfirmed desktop state.
- Fixed newly created Codex tasks remaining owned by the helper connection and therefore failing to open in the desktop application.
- WeChat response reads now stop reliably at the configured timeout instead of remaining stuck when an operating-system network implementation does not interrupt the body read promptly.
- Reviewed the public-repository security alerts and confirmed that the matches were test-only sample data and a browser cache name, not live API keys or company credentials. The source representation was adjusted to avoid repeated false positives.

## Upgrade notes

- No re-login, mobile password change, device pairing, or task-link change is required.
- Update both the computer DeskRelay installation and the public Relay, then restart both services safely.
- `--open-desktop-apps` only controls automatic application launch during daemon startup. Explicit actions from the web page or ClawBot do not require this option.

## Known limitations

- The public page still requires the computer DeskRelay daemon to be online. Running ChatGPT, WorkBuddy, or DeepSeek Harness alone does not make the public device online.
- WeChat completion and approval notifications remain subject to the WeChat context-token lifetime and may require a fresh incoming ClawBot message after a long idle period.
