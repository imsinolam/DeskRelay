# DeskRelay 2.1.2

Release date: 2026-08-17

## What changed

- The mobile web app now has a Settings page that shows whether each terminal supports task continuation, images, queues, approvals, and stopping, together with any missing local prerequisites.
- The mobile web app can temporarily enable Strict approvals. When enabled, every privileged action requires confirmation instead of automatically allowing low-risk actions or task-level approval bypasses.
- When several images are sent through ClawBot, DeskRelay now holds them until a complete instruction is provided, then sends the images and text as one task. Short descriptions are confirmed first, and users can keep the images while rewriting or cancel the draft.
- Progress and recent replies for very large Codex tasks now read only the necessary tail of the task data, reducing desktop resource usage during repeated viewing.

## Fixes

- Fixed cases where the desktop was still waiting for approval while the mobile task list, header, or approval card had already shown the request as handled. Mobile approval state now follows the actual desktop result, and actionable controls remain visible after a failed confirmation or timeout.
- Fixed cases where task-level approval bypass could hide a pending request from mobile and ClawBot even though the desktop had not actually accepted it.

## Upgrade notes

- This upgrade updates both the desktop DeskRelay installation and the public Relay, with a brief restart of both services.
- No sign-in, mobile password, or existing task-link changes are required.
- Strict approvals take effect immediately for the current process and return to the desktop environment default after a service restart.
- This version is deployed from the reviewed package and GitHub snapshot; it is not being published to the public npm registry in this release.

## Known limitations

- Sending messages, approving actions, stopping work, and creating tasks from the public web app still require the desktop to be online. When it is offline, only browser cache or the Relay's most recently verified read-only content is available.
- Proactive WeChat replies remain subject to the WeChat context validity window. DeskRelay can retry still-valid notifications after reconnection but cannot bypass the platform's time limits.
