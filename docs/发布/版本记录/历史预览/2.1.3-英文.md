# DeskRelay 2.1.3

Release date: 2026-08-17

## What changed

- The mobile Settings page now shows each terminal's actual availability: installed, not running, needs installation, or currently installing, together with its task-continuation behavior.
- For a small set of explicitly supported terminals, Settings now offers one-click installation. It runs only fixed installers registered by DeskRelay, never arbitrary user-provided commands, and automatically checks the result afterward.
- DeepSeek Harness, OpenCode, and other terminals now report command, service, and optional-configuration status separately instead of showing a generic online state when a prerequisite is missing.
- Settings now opens as a right-side drawer with a simpler terminal and task layout that is easier to use on a phone.

## Fixes

- Fixed terminals being marked unavailable when only an optional prerequisite was missing.
- Fixed the Settings page failing to distinguish installed software from a service that has not been started.
- Fixed differences between the capabilities and dependency information shown on mobile and the checks performed on the computer.

## Upgrade notes

- This upgrade updates both the desktop DeskRelay installation and the public Relay, with a brief restart of both services.
- No sign-in, mobile password, or existing task-link changes are required.
- One-click installation requires network access to the relevant package source. Some terminals still require a separate sign-in or desktop-app launch afterward.
- This version is deployed from the reviewed package and GitHub snapshot; it is not being published to the public npm registry in this release.

## Known limitations

- One-click installation currently covers only explicitly registered and reviewed installers. Desktop apps, account sign-in, and starting local services may still require manual action.
- Installation runs on the computer and continues if the mobile page is closed; the result is checked again after the service restarts.
- Sending messages, approving actions, stopping work, and creating tasks from the public web app still require the desktop to be online.
