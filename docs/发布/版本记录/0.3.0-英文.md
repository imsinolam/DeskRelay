# WeRelay 0.3.0

Release date: 2026-08-22

## What changed

- The project is now named WeRelay. The public repository, package, commands, configuration, and runtime directory use one consistent name, while desktop agents, mobile web, and ClawBot continue the same real task.
- When upgrading from DeskRelay, WeRelay copies existing WeChat login, device pairing, task state, and attachment records. The old directory is preserved and is not overwritten or deleted.
- Task links remain usable when the public connection is temporarily unstable. Mobile web now distinguishes an unreachable server from a computer that has not connected yet, and shows elapsed waiting time or retry progress.

## Fixed

- Fixed task links that could remain unusable when they were sent before alias registration completed.
- Fixed public-connection failures being presented as a computer-offline state without clear recovery feedback.
- Removed remaining old-brand labels from mobile web and the public Relay so one release no longer mixes two product names.

## Upgrade notes

- Uninstall the old `deskrelay` package and install `werelay`. The old `deskrelay-*` commands are no longer provided; use the corresponding `werelay-*` commands.
- Rename custom `DESKRELAY_*` settings to `WERELAY_*`, and upgrade and safely restart both the desktop service and the public Relay.
- Keep `~/.deskrelay` during the first WeRelay startup. The data is copied automatically, and you can archive the old directory after verifying the new installation.

## Known limitations

- This release does not automatically rename user-managed domains, certificates, system service names, or third-party scripts. Those deployment settings must be updated separately.
- WeChat completion and approval notifications still depend on a valid WeChat context. After a long idle period, sending a fresh message to ClawBot may be required.
