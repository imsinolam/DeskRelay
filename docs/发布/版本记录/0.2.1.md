# DeskRelay 0.2.1

发布日期：2026-08-18

## 这次更新

- GitHub 仓库的文档已按“使用指南、架构设计、开发协作、发布、官网素材”重新整理，常用入口改为清晰的中文名称，历史预览版本集中归档，查找和维护更直接。
- 新增局域网移动网页和公网 Relay 的首次使用说明，第一次设置移动访问密码、部署服务器和完成验收时都有可直接照做的步骤。
- 手机端切换终端时只显示“当前、切换中、处理中、待审批、待输入、启动中、异常”等需要关注的状态，减少重复的“已打开、已连接、未打开”提示。

## 修复的问题

- DeskRelay 后台启动、重启和自动恢复时不会自行打开 ChatGPT 或 WorkBuddy；用户从网页或 ClawBot 明确选择终端或任务时，仍可按需启动对应桌面应用。
- 修复桌面应用之前连接失败后，即使用户再次从手机明确切换也不能重新启动和连接的问题。
- 修复 Codex 审批请求在桌面通信超时或状态尚未确认时可能提前消失的问题；网页和 ClawBot 会继续显示真实待处理审批，直到桌面端确认完成。
- 修复新建 Codex 任务交给桌面应用时可能被辅助连接占用，导致桌面端无法继续打开同一任务的问题。

## 升级说明

- 升级后无需重新登录，也无需修改移动网页密码、设备配对或现有任务链接。
- 本次更新需要同时更新电脑端 DeskRelay 和公网 Relay，并安全重启两个服务。
- `--open-desktop-apps` 只用于允许后台启动阶段自动打开桌面应用；网页和 ClawBot 的明确用户操作不需要额外开启这个选项。

## 已知限制

- 公网网页仍要求电脑端 DeskRelay 在线；单独运行 ChatGPT、WorkBuddy 或 DeepSeek Harness 不代表公网设备已经在线。
- 微信完成通知和审批通知仍受微信上下文有效期影响，长时间没有新消息时，可能需要先向 ClawBot 发送一条新消息恢复上下文。
