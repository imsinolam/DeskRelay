# DeskRelay 2.1.1

Release date: 2026-08-16

## What changed

- The public Relay now prepares recent task lists, task status, and message tails before the browser opens. Public pages and recent task switches can show the last verified content sooner, then refresh changes silently in the background.
- Task links in WeChat completion notifications are shorter and no longer contain the fully encoded task identifier. Existing short links remain compatible, and newly issued links continue to resolve after a Relay restart.
- WeChat task lists, search results, and help text no longer include repetitive horizontal separators, making them easier to read on phones.

## Fixes

- Fixed a ClawBot failure mode where the long poll had received HTTP headers but stalled while reading the response body. The request now times out and reconnects instead of leaving the process apparently online while no new messages arrive.
- Fixed newly issued public task links becoming unavailable after a Relay restart. Their mappings are stored in a permission-restricted server state file.
- Fixed long-pressing a task in the open mobile sidebar also selecting the task title in the conversation behind it. Text selection and copying continue to work after the sidebar closes.
- When ClawBot receives a message containing only a number, it now tries the current approval first and then the recent task list. If the meaning is unclear, it asks the user instead of sending the bare number to the model.
- Fixed some restored Codex tasks showing a waiting-for-approval state without an actionable approval card in the conversation. Restored approvals can now be allowed or rejected from the matching task.

## Upgrade notes

- Update both the DeskRelay installation on the computer and the public Relay, then briefly restart both services.
- No new login or mobile password change is required. Existing `/t/...` task links remain compatible.
- The standard systemd deployment stores task-link mappings under `/var/lib/deskrelay`. Custom service configurations must provide a state directory writable only by the service account.
- This version is deployed from a reviewed package and GitHub snapshot and is not published to the public npm registry.

## Known limitations

- Sending messages, approvals, stops, and task creation through the public web page still require the computer to be online. When it is offline, only browser cache or the Relay's latest verified read-only content can be viewed.
- WeChat proactive replies remain subject to WeChat context expiration. DeskRelay can retry valid notifications after reconnection, but it cannot bypass the platform time limit.
