# DeskRelay 任务职责与协作规划

> 更新日期：2026-08-17
> 目标：让 ChatGPT/Codex 中 DeskRelay 项目的长期任务按稳定能力域分工，避免同一问题被多个任务重复实现、相互覆盖或分别发布。

## 1. 项目原则

DeskRelay 是本地 AI Agent 的跨屏任务延伸层。电脑端真实 Agent 是任务、上下文、工具和权限的唯一 owner；微信 ClawBot、局域网网页和公网网页只负责接入并继续原任务，不能创建隐藏的替代会话。

任务划分遵守以下规则：

1. 一个长期任务对应一个稳定能力域，不对应一个单独 Bug。
2. 产品任务不负责发布，发布任务不临时开发，审计任务不直接接普通功能。
3. 每项功能只能有一个开发 owner。
4. 开发任务只交付提交号、测试结果和验收清单，由发布任务统一整合部署。
5. 涉及多层的数据链路问题，按真实根因归属，而不是按用户看到的表象归属。

## 2. 当前任务与职责

### 2.1 DeskRelay｜产品与体验验收

- 任务 ID：`TASK-PRODUCT-ACCEPTANCE`
- 定位：产品负责人、需求入口和最终验收任务。

负责：

- 明确产品目标、用户场景和优先级。
- 评审微信、网页、电脑端三端体验。
- 复现问题并判断属于哪条技术链路。
- 编写清晰、可验证的验收标准。
- 协调对应工程任务处理问题。
- 发布后在真实手机和真实任务中完成最终验收。
- 守住“进入同一条真实任务，不创建第二条会话”的产品原则。

不负责：

- 不长期承担核心功能开发。
- 不直接推送 GitHub、安装或部署正式服务。
- 不把不同能力域的实现长期堆积在当前任务中。

标准输出：

```text
问题描述
用户期望
归属能力域
优先级
验收标准
```

### 2.2 DeskRelay｜核心运行时与 ClawBot

- 任务 ID：`TASK-CORE-RUNTIME`
- 定位：微信入口和 DeskRelay 本机常驻运行时的主要开发任务。

负责：

- 微信消息收发和长轮询。
- ClawBot 任务列表、搜索、选择和任务内发送。
- 纯数字的审批选项与任务序号判断。
- 微信图片暂存、批量合并、短文本确认和取消。
- 入站消息、完成通知、审批通知和任务链接去重。
- 消息排队、转向当前任务和过期控制。
- daemon 生命周期、持久化、自动恢复和重启通知。
- Relay Client 与公网服务器之间的设备连接。

主要代码范围：

```text
src/wechat/*
src/daemon/deskrelay-daemon.ts
src/daemon/daemon-state.ts
src/daemon/*delivery*
src/daemon/*deferred*
```

不负责：

- 不处理移动网页的视觉、排版和触摸交互。
- 不负责具体 Agent 的桌面协议实现。
- 不直接执行正式发布。

### 2.3 DeskRelay｜待合入修复清理

4. 归档本任务，不再复用。

### 2.4 DeskRelay｜发布与部署

- 任务 ID：`TASK-RELEASE-DEPLOY`
- 定位：DeskRelay 唯一正式发布任务。

负责：

- 接收明确的待发布提交列表和验收清单。
- 检查提交依赖、重复补丁和冲突。
- 在独立 release worktree 中整合版本。
- 更新版本号和中英文发布说明。
- 运行隐私检查、Lint、类型检查、完整测试、构建和打包检查。
- 生成不包含 `.git`、运行状态和本地隐私信息的公开快照。
- 通过 `publish-server.example` 的隔离目录提交并推送 GitHub。
- 安装本机正式版本。
- 部署 `relay-server.example` 的公网 Relay。
- 验证网页、API、WSS、设备在线、消息发送和回读。
- 保留可验证的回滚目录，并报告最终提交、版本和部署证据。

不负责：

- 不在发布过程中临时开发业务功能。
- 不把主工作区所有未提交修改一起发布。
- 不从 Mac 直接向 GitHub 推送。
- 不在验活失败时只给说明而不处理真实部署状态。

开发任务交接格式：

```text
提交号
功能说明
修改范围
测试结果
依赖提交
发布后验收清单
```

### 2.5 DeskRelay｜架构、质量与跨平台

- 任务 ID：`TASK-ARCHITECTURE-QUALITY`
- 定位：独立技术审计、架构治理和质量任务。

负责：

- 模块职责、依赖方向和循环依赖检查。
- 巨型文件、巨型类和跨层耦合的拆分规划。
- 安全边界、隐私扫描和公网风险审计。
- Windows、macOS、Linux 的跨平台兼容性。
- CI、测试覆盖、测试隔离和失败归因。
- worktree、旧分支和已发布等价提交的定期清理建议。
- 为技术债建立独立、可回滚的重构任务。

不负责：

- 不直接接按钮、排版、微信文案等普通产品需求。
- 审计发现的问题应交给对应工程 owner。
- 除明确的架构重构外，不在审计任务里实现业务功能。

### 2.6 DeskRelay｜官网、文档与演示

- 任务 ID：`TASK-DOCS-DEMO`
- 定位：产品表达、官网、文档和公开演示素材任务。

负责：

- 官网产品定位和中文文案。
- README、产品介绍、安装说明和安全说明。
- 演示数据、官网截图、视频和公开素材。
- 发布说明的用户语言审校。
- 统一表达“一条真实任务，每一块屏幕”。
- 避免演示素材泄露用户真实项目、任务和隐私信息。

不负责：

- 不修改运行时核心逻辑。
- 不为了截图污染用户真实任务数据。
- 不描述尚未发布或尚未真实验收的能力。

## 3. 建议新增的长期任务

## 4. 问题归属示例

### 审批问题

| 现象 | 归属任务 |
| --- | --- |
| Desktop 有审批，但 DeskRelay 没识别 | Agent 适配与桌面同步 |
| 已识别审批，但 ClawBot 没推送 | 核心运行时与 ClawBot |
| API 有审批，但网页没有卡片 | 移动网页与公网 Relay |
| 网页有卡片，但点击状态不能定位 | 移动网页与公网 Relay |
| 审批修复需要跨模块重构 | 架构、质量与跨平台先审查 |

### 消息重复问题

| 现象 | 归属任务 |
| --- | --- |
| 微信同一条入站消息被消费两次 | 核心运行时与 ClawBot |
| Agent Adapter 向同一任务提交两次 | Agent 适配与桌面同步 |
| API 只有一条，网页渲染成两条 | 移动网页与公网 Relay |
| 发布后本机与公网版本不一致 | 发布与部署 |

### 性能问题

| 现象 | 归属任务 |
| --- | --- |
| 微信长轮询卡死或重连慢 | 核心运行时与 ClawBot |
| Agent 历史读取过慢 | Agent 适配与桌面同步 |
| 网页首屏、正文和分页慢 | 移动网页与公网 Relay |
| 超长任务导致模块资源异常 | 架构、质量与跨平台 |

## 5. 标准协作流程

```text
用户反馈或新需求
        ↓
产品与体验验收：澄清目标、归类、写验收标准
        ↓
唯一工程 owner：实现、测试、提交
        ↓
架构与质量：检查跨模块风险和质量问题
        ↓
发布与部署：统一整合、发布、部署、线上验活
        ↓
产品与体验验收：真实手机和真实任务最终验收
```

官网、文档与演示任务从已经确认并发布的产品能力中提取内容，不提前宣传未发布功能。

## 6. 任务使用纪律

1. 不为每个 Bug 新建长期任务。
2. 一个任务连续出现三个不同能力域的需求时，必须停止并重新分流。
3. 产品与体验验收任务只定义需求和验收，不承担跨模块实现。
4. 开发任务不得自行部署正式版本。
5. 发布任务不得在发布过程中临时修改业务逻辑。
6. 审计任务保持独立性，不与被审计功能共用实现职责。
7. 多个任务可能修改同一巨型文件时，必须指定唯一 owner 或串行合入。
8. 发布完成后清理已发布的临时 worktree、等价旧分支和一次性验收任务。
9. 任务标题必须反映当前长期职责；一次性测试标题不得继续承载正式开发。
10. 所有线上完成结论必须包含真实版本、提交、健康状态和功能验收证据。
