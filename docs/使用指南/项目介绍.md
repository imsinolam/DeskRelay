# 关于 WeRelay

## 一句话定位

WeRelay 是本地 AI Agent 的跨屏任务延伸层：它把电脑上的真实任务接入微信 ClawBot、局域网网页和可选的公网网页，而不是在远端重新创建一个 Agent 会话。

## 核心原则

### 1. 电脑 Agent 是唯一 owner

Codex、WorkBuddy、Grok、Claude Code、DeepSeek Harness 等 Agent 继续持有：

- 任务历史与上下文；
- 项目目录和本地文件；
- 模型、账号与供应商配置；
- 工具权限、审批与运行状态。

WeRelay 不复制这些能力，也不把远程消息转给一条看不见的替代会话。

### 2. 远程入口只延伸，不分叉

微信 ClawBot、局域网网页和公网网页是三种操作入口。它们可以展示任务、发送消息、处理审批、停止运行和查看回复，但最终操作的仍是电脑端原任务。

### 3. 失败必须可见

电脑离线、Agent 未启动或真实任务无法恢复时，WeRelay 应明确提示不可用。它不能为了“看起来成功”而自动启动另一份 CLI/ACP 会话，因为那会造成上下文和聊天记录分叉。

## 四类界面的关系

| 界面 | 所在位置 | 主要用途 | 数据路径 |
| --- | --- | --- | --- |
| 电脑 Agent | 用户电脑 | 原生工作、持有真实任务 | Agent 与 WeRelay 本机通信 |
| 微信 ClawBot | 微信 | 快速选择任务、发消息、审批、接收完成通知 | Mac 主动连接微信服务 |
| 局域网网页 | 手机或另一台电脑 | 完整阅读、附件上传和多任务浏览 | 浏览器直接访问 Mac |
| 公网网页 | 任意外网浏览器 | 离开局域网后继续使用移动网页 | 浏览器 → Relay → Mac 主动连接 → 真实 Agent |

## WeRelay 不是什么

- 不是新的模型平台；
- 不是远程桌面；
- 不是通用文件浏览器；
- 不是任意 TCP/HTTP 代理；
- 不是把本地服务端口暴露到公网的穿透工具；
- 不是独立保存另一份任务历史的聊天镜像。

## 名称

“We”强调微信、网页与电脑上的真实 Agent 共同连接同一项任务；“Relay”强调产品只负责把必要的消息、状态和操作可靠地中继到其他屏幕。
